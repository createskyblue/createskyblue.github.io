Windows 熄屏后自动亮起时先检查空闲输入是否被重置

Windows 的“关闭显示器”和“系统睡眠”是两条不同路径。一次死机重启后，机器可以正常手动睡眠，但把显示器自动关闭时间设成 1 分钟后，屏幕会在熄灭后很快亮起。这个现象容易被误判成电源计划失效，实际排查入口应该先落到空闲输入计时。

现象

故障表现很窄：

  • 手动睡眠可以进入低功耗状态，按电源键可以正常恢复。
  • 把显示器自动关闭时间设为 1 分钟后，屏幕会按时熄灭，又很快重新亮起。
  • 机器没有表现出整机睡眠后被异常唤醒的特征。

这组现象说明，问题不一定在“睡眠唤醒”。显示器熄灭只需要满足用户空闲条件；只要 Windows 认为有新的鼠标、键盘、触控板或虚拟 HID 输入，显示器就会重新点亮。

先排除电源唤醒路径

第一步先看系统有没有明确的电源阻塞或唤醒来源。几个结果比较关键：

  • powercfg /requests 没有显示器、系统、执行、Away Mode 等保持唤醒请求。
  • powercfg /waketimers 没有活动唤醒计时器。
  • powercfg /devicequery wake_armed 没有列出允许唤醒系统的设备。
  • 电源事件记录里，手动睡眠后的恢复来源是电源按钮。

这些证据把问题范围收窄到显示器空闲路径。系统并没有被某个计划任务或设备从睡眠里唤醒，屏幕重新亮起更可能来自用户输入状态被刷新。

用空闲计时验证假输入

随后直接监控 Windows 的最后输入时间。正常情况下，如果没有碰鼠标、键盘和触控板，空闲秒数应该持续递增。实际观察到的情况是，空闲秒数接近显示器关闭阈值时会突然归零。

这个结果很关键。它说明系统收到了某种输入事件，或者某个驱动/服务让 Windows 认为用户刚刚操作过。于是显示器刚进入关闭状态，又立刻被“新输入”点亮。

这里的重点是先确定判断对象：从“电源计划坏了”切换到“谁在重置空闲输入计时”。排查方向一变，后续证据就容易对齐。

可疑对象集中在虚拟输入和虚拟显示

设备和进程列表里出现了几类强相关对象：

  • 远控或串流类服务。
  • 模拟器相关远程服务。
  • 虚拟显示适配器。
  • 虚拟 HID 鼠标、键盘和供应商定义设备。

这类组件为了远程控制、投屏、模拟触控或保持会话，常会安装虚拟输入设备和虚拟显示设备。它们不一定会阻止系统睡眠，也不一定出现在 powercfg /requests 里，但仍可能刷新用户输入状态。

本次机器上最终通过停用相关虚拟输入/显示服务解决。停用后重新测试 1 分钟自动熄屏，屏幕不再马上亮起。

修复边界

这次修复采用的是隔离式处理：

  • 只停用确认相关的虚拟输入/显示服务。
  • 不修改电源计划的核心参数。
  • 不禁用物理鼠标、键盘、触摸板和显卡。
  • 不卸载驱动，先保留回滚空间。

如果还需要使用远控、串流或模拟器功能，可以逐个恢复服务并重新测试。哪个服务恢复后让空闲计时再次归零，哪个服务就是后续处理对象。后续处理可以选择更新软件、关闭它的远程输入能力、禁用虚拟显示组件，或保留服务但只在需要时手动启动。

排查经验

这类问题要把“睡眠”和“熄屏”分开看。手动睡眠正常，只能说明 S3 睡眠链路和电源按钮恢复链路可用；它不能证明显示器空闲计时没有被重置。

比较稳的排查顺序是：

  1. 先看 powercfg /requests、唤醒定时器和唤醒设备，排除明确的电源阻塞。
  2. 再看事件日志，确认实际唤醒来源是否指向电源按钮、设备或计划任务。
  3. 如果电源路径没有异常，监控最后输入时间。
  4. 如果空闲时间无人操作时归零，优先检查虚拟 HID、远控、串流、模拟器、手写板、蓝牙键盘和触摸板服务。
  5. 只做可逆隔离，每次停一组相关服务，测试通过后再决定长期策略。

这次真正有用的分界点，是确认“屏幕自动亮起”来自空闲输入被刷新。只要这个判断成立，后续就应该停止反复调整电源计划，转向输入设备、虚拟驱动和后台服务。
